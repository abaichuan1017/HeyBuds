证据日期：2026-10-17，Asia/Shanghai。来源为本地冻结的 `OppoPodsManager-main`；没有将其 README 的历史数量当作代码现状。

| 原项目后端 | 本地目录 | 当前接入范围 |
| --- | --- | --- |

| vivo / iQOO | 43 个显示型号，完整保留 87 条原始变体与项目代号 | GAIA 握手／通知、电量、实时佩戴、固件、降噪、版本对应 EQ、游戏、空间音频、佩戴检测／听力保护、查找与多设备列表／连接 |

合计 **226 条目录记录**：137 + 43 + 24 + 18 + 1 + 3。系列规则不是具体产品，产品 ID 与显示型号也不是同一计数单位；不宣称 226 款均能连接或控制。

OPPO 系原有配置为 OPPO 56、OnePlus 32、realme 49。vivo 的原始 JSON 另存为 `VivoDeviceModels.json`，字节保真；归一化条目保留所有 `sourceEntries`。华为能力来自 `HuaweiModels.cs`，Apple 型号来自 `AppleModels.cs`，小米／漫步者系列来自对应 Factory/Models。导入脚本为 `scripts/import-brand-models.py`，参考项目不修改。

## 界面

保留 360pt 原生面板、顶部设备菜单、电量区、降噪按钮和原位置的强度菜单、多设备入口、高级功能分组、设置页及底栏。各品牌使用同一组件，只显示当前可以操作的功能，不新增品牌专用页面。无充电盒的设备在原电量区域显示单电池。

## 验证与限制

本次自动验证见 `VALIDATION.md` 最新记录。新增覆盖包括 GAIA 版本、华为 Legacy/MBB 真值向量、小米电量／低延迟／认证结果真值帧、全部拆包边界、损坏 CRC、漫步者末字节／校验和、未知电量／真实零电量、跨品牌禁止写入、设置 ACK 与回读分离、断连取消、完整多设备列表及当前 Mac 保护。认证算法用独立执行上游轮函数生成的三个固定挑战向量核对；这证明移植一致，不代表真实小米认证已验收。

- 新增品牌目前均为源码／模拟协议验证，**没有新增品牌实机通过记录**。Air5 Pro 的本地观察不扩展到其他品牌。
- 小米配置响应字段仍需实机核对；未确认时保留未知，不以通用 ACK 填开关状态。
- vivo TWS 3e 强制双连无用户开关，沿用原表隐藏；其他 vivo 型号没有确认的双连使能回读时保留未知，避免以列表推断开关。
- AirPods / Beats 明文广播必须能绑定所选设备的名称；匿名、加密、无法区分的广播不显示为当前耳机电量。macOS 不一定持续提供这类广播，读不到时如实显示未知／无法建立读取会话。
- 华为标准 SPP 必须通过型号识别和有效协议响应；不使用固定猜测通道。没有有效 SDP 记录的设备不能以硬编码端口绕过。
- 原项目未开放的华为空间音频、查找、未解释的 MBB 分片、OTA、解除配对和健康测量流程不扩展为功能承诺。
